# 终末地 QTE 冷却助手

Windows 桌面悬浮助手：读取左下角头像下方、蓝色血条上方的细进度条，在屏幕中央显示四个角色的 QTE 冷却状态。仅使用屏幕截图，不修改游戏文件、不读取游戏内存、不注入游戏进程，也不会自动按键。

## 运行

从 Releases 下载 EXE，或下载 ZIP 并解压后运行。切换到新版前，请从旧版托盘菜单选择“退出”。

| 下载版本 | .NET 要求 |
| --- | --- |
| `EndfieldQteHelper-v1.1.0.exe` / `EndfieldQteHelper-v1.1.0-win-x64.zip` | 完整版，包含运行时，无需另装 .NET |
| `EndfieldQteHelper-v1.1.0-win-x64-framework-dependent.zip` | 精简版，不包含运行时；需要安装 **.NET 8 Desktop Runtime，Windows x64** |

精简版的[运行时官方下载页](https://dotnet.microsoft.com/en-us/download/dotnet/8.0)：选择 **.NET Desktop Runtime → Windows → x64**，仅安装普通 .NET Runtime 不够。已有兼容的 .NET 8 桌面运行时可直接启动。本地完整包位于 `dist/v1.1.0/win-x64/`，精简包位于 `dist/v1.1.0/win-x64-framework-dependent/`。

1. 游戏使用**无边框窗口**或**窗口模式**，在助手中选择游戏所在显示器。
2. 点击“开始检测”，核对实时采样中的黄框是否位于 QTE 细条，青框是否位于紧邻下方的蓝色血条。
3. 默认区域依据提供的 2560 × 1440 截图设置，按屏幕高度缩放，并保持左下角锚定。不同 HUD 缩放、窗口尺寸、窗口位置需要校准。
4. 点击“校准四条进度条”。助手隐藏后会冻结当前屏幕。从左到右依次框选四条细进度条的**内部完整宽度**，不要框入头像、边框或下方蓝条。右上角有放大镜。Backspace 撤销，Enter 保存，Esc 取消。校准时游戏 HUD 必须已显示。
5. 点击“调整悬浮位置”拖动标记，再锁定。锁定后鼠标穿透，不阻挡游戏操作。
6. 可修改角色名称、标记大小、就绪亮度和进度亮度，以及开启就绪提示音。“收到托盘”隐藏设置窗口，双击托盘图标重新打开。关闭设置窗口或选择托盘“退出”会结束助手。

| 标记 | 含义 |
| --- | --- |
| 绿色 / 就绪 | QTE 条已变白并填满，连续 3 帧确认 |
| 灰色 / 冷却中 | 浅灰扇区表示已恢复进度，深灰表示尚未恢复；状态连续 2 帧确认 |
| 黄色 / 未识别 | 未找到可验证的 HUD、截图失败、暂停或尚未完成确认 |

悬浮层仅显示编号 1–4 的四个圆，整体不透明度为 50%，用绿、灰、黄三种颜色区分状态；不显示底板、边框、角色名称或状态文字。编号始终对应左下角从左到右的队伍槽位。调整位置时拖动任意圆即可。角色名称仅保留在设置窗口。QTE 冷却完成并不等于触发条件已经满足；工具不识别触发条件或剩余秒数。

冷却扇区从 12 点方向顺时针填充，25% 为四分之一圆，50% 为半圆。读取原进度条从左侧连续填充的长度，每 100 ms 更新，不使用推算的冷却秒数。浅灰填满仍需白条确认后才显示绿色。

“进度亮度”默认 120，用来区分较亮的灰色填充与深灰空槽；“就绪亮度”默认 220，只影响白条就绪判定。若进度长期为零，可适当降低进度亮度；若空槽也显示进度，则提高它。现有参考截图只有空条和白色满条，中间灰色进度使用合成图验证，实际灰阶可能需要调整。

## 快捷键

- `Ctrl + Alt + F8`：调整 / 锁定悬浮位置。
- `Ctrl + Alt + F9`：暂停 / 继续识别。
- `Ctrl + Alt + F10`：隐藏 / 显示标记。

快捷键冲突会在设置中提示，仍可使用按钮和托盘菜单。

## 识别与限制

每 100 ms 只截取包含四条 QTE 条及血条的窄区域。以亮度、低色差、横向白色覆盖率和末端覆盖判定就绪，用蓝色血条验证采样位置。画面不可识别时立即清空旧状态，不继续显示旧的就绪结果。提示音只在已经确认的“冷却中 → 就绪”时播放。

- 需要游戏画面在桌面上可见；被其他窗口遮挡、最小化或独占全屏时可能无法读取或显示叠加层。
- UI 隐藏、濒死 / 空血条、强特效遮挡、HDR 亮度映射或颜色滤镜可能导致未识别，需要调整阈值或校准。本实现尚未经过真实战斗连续运行验证。
- 显示器分辨率或布局改变后会暂停检测并要求核对区域。移动游戏窗口、改变游戏 UI 缩放后也需要重新校准。
- 只凭画面颜色不能保证所有场景无误判。默认就绪覆盖门槛为 98.5%，另检查进度条末端；帧确认会引入约 0.2–0.3 秒延迟。
- 配置保存在 `%LOCALAPPDATA%/EndfieldQteHelper/settings.json`，截图仅在内存处理，不录制或上传。

## 开发与验证

安装 .NET 8 SDK 后，在项目根目录执行：

```powershell
.\scripts\build.ps1
# 不包含 .NET 的精简版：
.\scripts\build.ps1 -FrameworkDependent
# 临时指定下一版本：
.\scripts\build.ps1 -Version 1.1.1
```

默认版本在 `Directory.Build.props` 中维护。脚本会发布 Windows x64 独立 EXE、运行内置验证，并生成 ZIP 和 SHA256 校验文件。输出格式为 `dist/v<版本>/win-x64/EndfieldQteHelper-v<版本>.exe`，每个版本单独存放。即使直接执行 `dotnet build` 或 `dotnet publish`，EXE 名称也包含版本号。发布前请更新默认版本和 `CHANGELOG.md`，同一版本正在运行时需要先退出再重新打包。

`-FrameworkDependent` 使用独立目录与 `-framework-dependent` 文件名后缀，生成单文件 EXE 和 ZIP；校验文件为 `SHA256SUMS-framework-dependent.txt`，不会覆盖完整版校验文件。构建精简版时，本机也需要 .NET 8 桌面运行时来运行验证。

无外部 NuGet 库。代码包括屏幕抓取、识别、防抖、校准、悬浮窗及设置窗口。莱万汀像素图标用于 EXE、设置窗口和托盘，详见 [图标说明](assets/NOTICE.md)。

运行内置验证并查看报告（WinExe 需等待进程退出）：

```powershell
Start-Process -FilePath .\dist\v1.1.0\win-x64\EndfieldQteHelper-v1.1.0.exe -ArgumentList '--self-test verification.json' -Wait
Get-Content .\verification.json
```

`--self-test <报告路径> [图一完整截图路径] [图三完整截图路径]` 可增加真实截图回归，预期图一全部就绪、图三只有 1 号冷却。每张参考图还会检查 1920/2560/3840 宽度缩放。内置用例覆盖全白、灰条、部分填充、临近填满、HUD 缺失、颜色干扰、越界、连续帧确认与失效清空。

`--render-preview <输出目录>` 生成设置界面和标记的静态预览，供布局检查。
